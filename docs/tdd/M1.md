#### `razti.shared.engine`
```clojure
(defn enqueue-input [room input])   ; T6: conj a :room/inputs solo si :playing
(defn apply-input [room input])     ; despacha :move | :bomb | :leave; actualiza :player/last-seq si trae :seq
(defn move-player [room player-id dir])
(defn place-bomb [room player-id])
(defn blast-cells [grid origin radius])  ; R6 + T2
(defn tick-game [room])
```
- **`move-player`:** no-op si el jugador no existe o está muerto. Fija `:player/dir dir` siempre (T1). Si `cooldown > 0` → nada más. Destino `(grid/step pos dir)`: bloqueado si está fuera, si `cell` ≠ 0, o si hay una bomba en el destino y el jugador no está en su `:bomb/pass-through`. Si avanza: nueva `:player/pos`, `:player/cooldown move-cooldown-ticks`, y se quita su id del `:bomb/pass-through` de la bomba de la celda que deja (R9).
- **`place-bomb`:** no-op si el jugador está muerto, si ya tiene `max-bombs-per-player` bombas activas (R3) o si su celda ya tiene una bomba (D8). Crea `{:bomb/id (str "b-" n) :bomb/owner id :bomb/pos pos :bomb/ticks-left bomb-fuse-ticks :bomb/radius bomb-radius :bomb/pass-through <ids de jugadores vivos en pos>}` con `n = :room/next-id` y lo incrementa (T4).
- **`blast-cells`:** incluye `origin`; por cada dirección, de 1 a `radius`: fuera de la grilla o `1` → para sin incluir; `2` → incluye y para; `0` → incluye y sigue. No se detiene en bombas (T2). Devuelve un vector en orden: origen, luego `:up :down :left :right`.
- **`apply-input` con `:leave`** (R11, T7): `:player/alive? false`.
- **`tick-game`** (no-op si no está en `:playing`). En este orden:
  0. Descontar `:player/cooldown` (mínimo 0) a todos (T1).
  1. Aplicar `:room/inputs` en orden con `apply-input` y vaciar la cola (R10.1).
  2. Descontar `:bomb/ticks-left` en 1 (R10.2).
  3. Detonar (R10.3, R7, T3, T4): las bombas con `ticks-left ≤ 0` explotan; toda bomba en las celdas de un blast de este tick explota también, hasta el punto fijo. Por cada bomba detonada, un blast `{:blast/id (str "bl-" n) :blast/cells (blast-cells grid-anterior pos radius) :blast/ticks-left blast-ticks}`. Se quitan de `:room/bombs`. Los `2` alcanzados pasan a `0`; si hubo cambio, `:room/grid-version` + 1.
  4. Daño (R8, R10.4): todo jugador vivo en una celda de cualquier blast activo → `:player/alive? false`.
  5. Descontar `:blast/ticks-left`; quitar los que llegan a 0 (R10.5). Un blast creado en el tick *t* hace daño en *t…t+9*.
  6. Victoria (R10.6, T5).
  7. `:room/tick` + 1.

#### `razti.shared.lobby`
Cada función devuelve `{:room room'}` o `{:error <kw>}`.
```clojure
(defn new-room [{:keys [code player-id name grid spawns]}])   ; → room en :waiting con el creador
(defn join-room [room {:keys [code player-id name]}])
(defn leave-room [room player-id])
(defn start-game [room player-id])
(defn restart [room player-id])
(defn empty-room? [room])          ; → true si no queda ningún jugador conectado (actualizado 2026-11-18)
```
- **`new-room`:** `:room/status :waiting`, `:room/owner player-id`, `:room/tick 0`, `:room/next-id 1` (el creador usa el 0; actualizado 2026-11-18), `:room/grid grid`, `:room/initial-grid grid`, `:room/spawns spawns`, `:room/grid-version 0`, `:room/inputs []`, `:room/bombs []`, `:room/blasts []`, `:room/winner nil`, y el creador con `join-order 0`. El código lo genera el servidor (único punto aleatorio).
- **`join-room`** — errores, en este orden: código distinto → `:room-not-found`; estado ≠ `:waiting` → `:game-in-progress`; `player-id` ya presente → `:already-joined`; 4 jugadores → `:room-full`; nombre repetido → `:name-taken` (D6c). Si no hay error: agrega al jugador con `:player/join-order` = `:room/next-id` (y lo incrementa), `:player/connected? true`, `:player/alive? true`, `:player/pos nil`, `:player/dir :down`, `:player/cooldown 0`, `:player/last-seq 0`.
- **`leave-room`:** `:playing` → `:player/connected? false` + `enqueue-input {:player-id id :action :leave}` (T7). Otro estado → quita al jugador. En ambos casos, si era el dueño, el dueño pasa al conectado con menor `join-order` (D6a); si no queda nadie conectado, `:room/owner nil`. Jugador inexistente → `{:room room}` sin cambios.
- **`start-game`** — errores: no es el dueño → `:not-owner`; estado ≠ `:waiting` → `:invalid-status`; menos de 2 jugadores → `:not-enough-players`. Si no hay error: `:playing`, grilla = `:room/initial-grid`, `grid-version` + 1, bombas, blasts e inputs vacíos, `tick 0`, `winner nil`, y a cada jugador (por `join-order`) `pos (nth spawns i)`, `alive? true`, `cooldown 0`, `dir :down`, `last-seq 0` (T10).
- **`restart`** (D6b, T8) — errores: `:not-owner`; estado ≠ `:finished` → `:invalid-status`. Quita a los desconectados y aplica `start-game` saltando el chequeo de `:waiting` (puede devolver `:not-enough-players`).

### §5 Contratos de datos (Malli, `razti.shared.specs`)
```clojure
(def Pos [:tuple :int :int])
(def Dir [:enum :up :down :left :right])
(def Nickname [:re #"^[A-Za-z0-9_-]{1,12}$"])
(def RoomCode [:re #"^[ABCDEFGHJKLMNPQRSTUVWXYZ2-9]{5}$"])
(def PlayerId [:string {:min 1 :max 64}])
(def Player [:map [:player/id PlayerId] [:player/name Nickname] [:player/pos [:maybe Pos]]
             [:player/dir Dir] [:player/alive? :boolean] [:player/cooldown nat-int?]
             [:player/last-seq nat-int?] [:player/join-order nat-int?] [:player/connected? :boolean]])
(def Bomb [:map [:bomb/id :string] [:bomb/owner PlayerId] [:bomb/pos Pos] [:bomb/ticks-left :int]
           [:bomb/radius pos-int?] [:bomb/pass-through [:set PlayerId]]])
(def Blast [:map [:blast/id :string] [:blast/cells [:vector Pos]] [:blast/ticks-left :int]])
(def Grid [:vector [:vector [:enum 0 1 2]]])
(def Input [:multi {:dispatch :action}
            [:move  [:map [:player-id PlayerId] [:action [:= :move]] [:dir Dir] [:seq {:optional true} nat-int?]]]
            [:bomb  [:map [:player-id PlayerId] [:action [:= :bomb]] [:seq {:optional true} nat-int?]]]
            [:leave [:map [:player-id PlayerId] [:action [:= :leave]]]]])
(def Room [:map [:room/code RoomCode] [:room/status [:enum :waiting :playing :finished]]
           [:room/owner [:maybe PlayerId]] [:room/tick nat-int?] [:room/next-id nat-int?]
           [:room/grid Grid] [:room/initial-grid Grid] [:room/spawns [:vector Pos]]
           [:room/grid-version nat-int?] [:room/inputs [:vector Input]]
           [:room/players [:map-of PlayerId Player]] [:room/bombs [:vector Bomb]]
           [:room/blasts [:vector Blast]] [:room/winner [:maybe [:or PlayerId [:= :draw]]]]])
;; Eventos del cliente (frontera, S02). El servidor añade :player-id desde la sesión.
(def ClientEvent [:multi {:dispatch first}
  [:razti/create-room [:tuple [:= :razti/create-room] [:map [:name Nickname]]]]
  [:razti/join-room   [:tuple [:= :razti/join-room] [:map [:code RoomCode] [:name Nickname]]]]
  [:razti/start-game  [:tuple [:= :razti/start-game] [:map]]]
  [:razti/restart     [:tuple [:= :razti/restart] [:map]]]
  [:razti/input       [:tuple [:= :razti/input] [:map [:seq nat-int?] [:action [:enum :move :bomb]]
                                                      [:dir {:optional true} Dir]]]]])
```
`:player/pos` es `nil` en `:waiting`. Los ids de las pruebas son `"p1"`, `"p2"`…
