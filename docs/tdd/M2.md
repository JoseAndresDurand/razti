- **`env-config`** (pura, probada): `RAZTI_HOST` (por defecto `"127.0.0.1"`), `RAZTI_PORT` (por defecto 3000; entero 1–65535, si no, `ex-info`), `:allowed-origins` = `#{"http://127.0.0.1:<port>" "http://localhost:<port>"}` ∪ Codespaces (si existen `CODESPACE_NAME` y `GITHUB_CODESPACES_PORT_FORWARDING_DOMAIN`: `"https://<name>-<port>.<domain>"`) ∪ `RAZTI_ALLOWED_ORIGINS` (separado por comas, sin espacios, solo `http(s)://host[:puerto]`; lo demás se ignora con aviso). `:dev?` = propiedad `razti.dev` = `"true"`.

- **`index.html`**: se lee una vez de `public/index.html` y se reemplaza `{{csrf-token}}` por el token de la sesión (base64url: sin caracteres que escapar). `Cache-Control: no-store`.
- **`start!`**: crea el estado de salas, Sente (`ws/make-sente`), el reloj y el barrido; arranca http-kit con `{:ip host :port port :legacy-return-value? false}` y registra `RAZTI escuchando en http://<host>:<puerto-real>` (con `port 0` usa el puerto real, para las pruebas). `-main` añade un shutdown hook con `stop!`.
- `(set! *warn-on-reflection* true)` en cada namespace de `src/clj`. Registro con una función `log` (hora ISO + nivel + mensaje) en `razti.server.core`.

#### `razti.server.ws`
```clojure
(defn make-sente [cfg])              ; → {:ch-recv :send-fn :connected-uids :ajax-post-fn :ajax-get-or-ws-handshake-fn}
(defn handle-event! [system ev-msg]) ; router (multimetodo por :id o case)
(defn send-room! [system code ev])   ; envía ev a cada uid conectado de la sala
(defn start-router! [system])        ; sente/start-server-chsk-router! → fn de parada
```
- **Sente:** adaptador http-kit, `:packer (transit/get-packer)`, `:allowed-origins (:allowed-origins cfg)`, `:csrf-token-fn` por defecto (lee `[:session :csrf-token]`), `:user-id-fn` por defecto (`[:session :uid]`).
- **Router:** eventos `:chsk/*` primero: `:chsk/uidport-close` → `rooms/leave!` (R11, T18); los demás `:chsk/*` se ignoran. Para el resto: si `(specs/valid-client-event? [id data])` es falso → se descarta y se registra a nivel `warn` (sin respuesta). Si el uid supera el límite (T16) → se descarta en silencio. Si no:

| Evento | Acción | Respuesta (`?reply-fn`) y envíos |
| :--- | :--- | :--- |
| `:razti/echo {:t n}` | — | `{:t n}` |
| `:razti/create-room {:name}` | `rooms/create!` | `{:ok {:code}}` o `{:error kw}`; `[:razti/room view]` a la sala |
| `:razti/join-room {:code :name}` | `rooms/join!` | `{:ok {:code}}` o `{:error kw}`; `[:razti/room view]` a la sala |
| `:razti/leave-room {}` | `rooms/leave!` | `{:ok {}}`; `[:razti/room view]` a los que quedan |
| `:razti/start-game {}` | `rooms/start!` + `loop/start-clock!` | `{:ok {}}` o `{:error kw}`; `[:razti/room view]` |
| `:razti/restart {}` | `rooms/restart!` + `loop/start-clock!` | igual |
| `:razti/input {:seq :action :dir?}` | `swap!` con `engine/enqueue-input` y `:player-id` = uid de la sesión (nunca del cliente) | sin respuesta |

  Todo evento válido de un jugador marca actividad de su sala (T15). Errores de `rooms`/`lobby` se responden tal cual (`:room-full`, `:name-taken`, `:server-full`, `:already-in-room`, `:not-in-room`, `:not-owner`, …).
- **Vista de sala** `[:razti/room view]` (lobby y resultado): `{:code :status :owner :winner :players [{:id :name :join-order :connected? :alive?}…] (ordenados por join-order)}`.

#### `razti.server.rooms`
Estado: `(atom {:rooms {code {:room (atom room) :last-activity-ms n :clock nil}} :uid->code {uid code}})`.
```clojure
(defn new-state [])
(defn new-code [taken])                         ; SecureRandom sobre config/room-code-alphabet; reintenta si choca
(defn create! [state uid player-name now-ms])   ; → {:ok code} | {:error :server-full | :already-in-room}
(defn join! [state uid code player-name now-ms])
(defn leave! [state uid now-ms])                ; → {:ok code} | {:error :not-in-room}
(defn start! [state uid now-ms])  (defn restart! [state uid now-ms])
(defn room-of [state uid])                      ; → atom de la sala o nil
(defn touch! [state code now-ms])
(defn sweep! [state now-ms])                    ; → códigos eliminados (T15)
(defn view [room])                              ; → vista de sala
```
- `create!` usa `lobby/new-room` con `campus/INITIAL-GRID` y `campus/SPAWNS`; máximo `config/max-rooms`.
- Las transiciones usan `lobby/*` dentro de `swap!` del atom de la sala; el resultado (`{:room}`/`{:error}`) se recupera con un `volatile!` escrito dentro de la función del `swap!` (el último intento gana).
- `leave!` quita `uid->code`; si `lobby/empty-room?` → elimina la sala y cancela su reloj.
- `sweep!`: elimina salas `empty-room?` o con `now - last-activity ≥ config/room-idle-ms`; a sus jugadores conectados se les envía `[:razti/error {:reason :room-closed}]` (lo hace `ws` con los códigos devueltos).
- El reloj (`now-ms`) se inyecta: las pruebas no dependen del tiempo real.

#### `razti.server.loop`
```clojure
(defn new-executor [])                        ; ScheduledThreadPoolExecutor de 2 hilos, daemon
(defn start-clock! [system code])             ; scheduleAtFixedRate 0 / config/tick-ms ms; idempotente
(defn stop-clock! [system code])
(defn snapshot [room last-grid-version])      ; pura: → snapshot (T14)
```
- Cada tick: `(swap! room engine/tick-game)` → `snapshot` → `ws/send-room!` con `[:razti/snapshot s]`. Si el estado pasa a `:finished`: último snapshot, `[:razti/room view]` y el reloj se cancela. Toda excepción del tick se captura y se registra (una tarea programada que lanza se cancela en silencio).
- **Snapshot:** `{:tick :status :winner :grid-version :players {uid {:name :pos :dir :alive? :join-order :last-seq}} :bombs [{:pos :ticks-left}] :blasts [{:cells}]}`, y `:grid` solo si `grid-version` difiere de la última enviada a esa sala (C11).

#### Cliente (`src/cljs/razti/client/`), sin dependencias npm de runtime
- **`core.cljs`**: `init` (punto de entrada); estado `(defonce app (atom {:screen :lobby :conn {:open? false :type nil :echo-ms nil} :room nil :snapshot nil :grid nil :me nil :error nil}))`; vistas por `hidden` sobre `#lobby`, `#room`, `#game`; textos con `textContent` (nunca `innerHTML`); botones: Crear sala, Unirse, Iniciar partida (solo dueño y ≥ 2), Salir, Reiniciar (solo dueño, en `:finished`). Mensajes de error en español (tabla abajo).
- **`ws.cljs`**: `make-channel-socket-client! "/chsk" <token de <meta name="csrf-token">> {:type :auto :packer (transit/get-packer)}`; al abrir: `:razti/echo` con `performance.now()` y guarda `:echo-ms`; `[:razti/room]`, `[:razti/snapshot]` y `[:razti/error]` actualizan `app`.
- **`input.cljs`**: `keydown` W/A/S/D y flechas → `:move` con dir; Espacio → `:bomb`; `seq` creciente desde 1; solo en `:screen :game` con el foco fuera de inputs; `preventDefault` en flechas y Espacio. La tecla `G` alterna el overlay de grilla solo si `goog.DEBUG` (C28).
- **`render.cljs`**: bucle `requestAnimationFrame` que dibuja el último snapshot (sin interpolación: S03). Capas: mapa (`imageSmoothingEnabled = false`) → soft-blocks (caja marrón `#8B5A2B` con borde `#5C3A1A`) → bombas (círculo negro, radio 14 px, chispa que parpadea más rápido con menos `ticks-left`) → blasts (celdas `#FFB000` con núcleo `#FFF2A8`) → jugadores vivos (sprite 40×40; fila 0 `:down`, 1 `:up`, 2 `:right`, `:left` = fila 2 espejada; cuadro 1–2 alternando cada 150 ms durante 200 ms tras cambiar de posición; si no, cuadro 0) → nombre encima (12 px, blanco con contorno negro) → overlay de grilla (C28: líneas y `1` en rojo translúcido).
- **Color por jugador (T20):** al cargar `player-sprites.png` se generan 4 hojas en canvas fuera de pantalla. Píxeles con tono HSL en 200°–250° y saturación > 0.25 cambian al tono del color del jugador (`join-order` → `config/player-colors`) conservando la luminosidad; la hoja 0 (azul) queda igual.
- **Mensajes de error:** `:room-full` «La sala está llena (4 jugadores).» · `:room-not-found` «No existe una sala con ese código.» · `:name-taken` «Ese nombre ya está en la sala.» · `:game-in-progress` «La partida ya empezó.» · `:server-full` «El servidor está lleno; prueba más tarde.» · `:already-in-room` «Ya estás en una sala.» · `:not-enough-players` «Se necesitan al menos 2 jugadores.» · `:room-closed` «La sala se cerró por inactividad.» · otro → «No se pudo completar la acción.»
- **Barra de estado** (esqueleto WAN, T21): `#status` muestra «Conexión: WebSocket · eco N ms», «Conexión: Ajax (sin WebSocket) · eco N ms» o «Desconectado».
